- `scripts/android-release.sh`: refuses unless the tree is clean, on main and equal to `origin/main` after a fetch (checked before anything else, so a dirty tree is refused even when there is nothing to publish); build N = `git rev-list --count HEAD`, versionCode N, versionName `<Cargo version>+N`; skips (exit 0) when nothing under `android/` changed since the newest `android-*` tag, unless `--force`; signs from `POPCORNSTASH_KEYSTORE_B64` (a mode-600 temp file deleted on exit) or `POPCORNSTASH_KEYSTORE`; verifies with apksigner (one signer, its SHA-256 equal to `android/release-cert.sha256`, refusing without that file) and aapt2 (package, versionCode, versionName); creates the release as a draft pre-release `android-N` named "Android app, build N" on HEAD with the commit and the subjects of the android/ commits since the last build, uploads `popcornstash-android-N.apk` and its `.sha256` to `GITHUB_UPLOADS_URL`, then publishes it. `GITHUB_RELEASE_TOKEN` is sent as a Bearer token only when set and never printed. `android/release-cert.sha256` is not committed yet: the owner makes the key (README, Releasing).
- The app (`update/`): `UpdateChecker` (public release list, no login, its own client with the app's name and version as User-Agent, ETag and If-None-Match, rate limit and offline told apart), `AppBuilds` (highest `android-N` that is not a draft and has both files, offered only when higher than `BuildConfig.VERSION_CODE`), `UpdateFetcher` (download to `cacheDir/updates`, SHA-256, then package, build and signer from PackageManager; every failure deletes the file), `PackageInstallerUpdates` and `UpdateInstallReceiver` (permission page first, a session with USER_ACTION_NOT_REQUIRED on Android 12 and later, Android's confirmation opened, outcomes reported, file deleted), `WorkManagerUpdateJobs` (daily check on any network, on by default; one download job with a progress notification), `AppUpdates` (the states). A copy signed with another key (`BuildConfig.RELEASE_CERT_SHA256` from the cert file) is told so before downloading and offered the release page. Settings has "This app" (version and build, one sentence per state with at most one action, the switch for the daily check). The Settings screen changes are a parameter on `SettingsRootPage` and `SettingsTab` plus new files; existing screenshots are unchanged.

Android updater, review fixes (2026-10-14). Main (the right-edge bar) merged into the branch first; every finding checked against the code before fixing.
- Safety: a download signed with another key than a release-signed copy's is now refused and deleted ("Build 415 was not signed by PopcornStash.", "Do not install it by hand; tell the owner."), never sent to the release page. "Needs a one-time reinstall" (OtherKey) is only for a copy known not to be release-signed: a debug build (`BuildConfig.DEBUG`, which every phone runs today) or a certificate other than `android/release-cert.sha256`; it is told before any download and gets no daily notification. A non-debug copy built without the cert file fails closed the same way as a release-signed one.
- Robustness: downloads stop past the size the list or the server gave, past 200 MB, or after 60 minutes, and a list that declares more than 200 MB is not offered; the manifest declares UPDATE_PACKAGES_WITHOUT_USER_ACTION (the platform's setRequireUserAction docs in the SDK 37.2 sources list it); Android 9 and 10 read an archive's certificates with GET_SIGNATURES as well (the Android 11 framework, disassembled from Robolectric's jar, reads them for either flag; the Android 9 framework could not be checked here, because Maven Central rate-limited its jar, so the fix follows the reviewer and asking for both flags is harmless on every release); a missing or unreadable verified file, a session Android refuses (now created inside the try) and any RuntimeException from the installer end in a stated failure instead of crashing the app scope; a replaced download job waits for the old one's files, and only the newest job reports.
- Installing: Android's confirmation is kept (`PackageInstallerUpdates.pendingConfirmation`) and "Install" shows it again; back on the page with no session of the app's left, it goes back to the verified file; closing the confirmation keeps the file ("Build 415 was not installed." with Install). PackageInstaller's statuses become plain sentences (storage, incompatible, conflict, blocked, damaged, other); Android's own message goes to the log only.
- Notifications: none for a build this copy cannot install; a vanished higher build lowers `lastNotified`; only release pages of this repository open.
